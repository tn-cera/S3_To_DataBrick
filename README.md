# Databricks to Amazon S3 — Unity Catalog Setup Guide

## 1. Purpose

This guide documents the steps for configuring Databricks Unity Catalog to read files from a private Amazon S3 bucket using an AWS IAM role, a Databricks storage credential, and an external location.

**This document intentionally contains no website addresses, S3 addresses, bucket paths, or copyable cloud-resource addresses.** Enter the actual values directly in your own AWS and Databricks environments when following the steps.

## 2. Components and how they work together

1. **IAM permissions policy:** defines what the AWS role can do in S3.
2. **IAM trust policy:** defines which Databricks identity can assume the AWS role and which External ID must be supplied.
3. **Databricks storage credential:** stores the reference to the AWS IAM role.
4. **External location:** associates the S3 bucket or folder with a storage credential.
5. **Unity Catalog privileges:** control which Databricks users or groups can read or write through the external location.

A storage credential and an external location are different objects. Creating either one does not, by itself, prove that end-to-end access works.

---

## 3. Step 1 — Create an IAM role in AWS

1. Open the AWS Management Console.
2. Go to **IAM → Roles**.
3. Choose **Create role**.
4. Follow the custom trust-policy workflow if you are creating the role before creating the Databricks credential.
5. Name the role:

   `DatabricksS3ReadAccess`

6. Complete the role creation.
7. Copy the role's **IAM Role ARN** from the role summary. Keep it available for the Databricks credential form.

**Important:** An IAM role ARN identifies an IAM role. It is not the same thing as an S3 bucket ARN. In the Databricks storage credential form, provide the IAM role ARN, not the bucket ARN.

---

## 4. Step 2 — Add read permissions to the IAM role

1. Open the `DatabricksS3ReadAccess` role.
2. Select **Permissions → Add permissions → Create inline policy**.
3. Open the JSON editor.
4. Add this read-only policy, replacing the bucket-name placeholder with your own bucket name in both resource entries:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:ListBucket"
      ],
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME"
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject"
      ],
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/*"
    }
  ]
}
```

5. Choose **Next**.
6. Give the policy a descriptive name, such as `DatabricksS3ReadAccessPolicy`.
7. Save it and confirm that it appears under the role's Permissions tab.

### What these permissions do

| Permission | Purpose |
|---|---|
| `s3:ListBucket` | Allows listing objects in the bucket. |
| `s3:GetObject` | Allows reading objects and their metadata. |

This policy is read-only. It does not grant upload or delete access.

**If the bucket uses SSE-KMS encryption:** The IAM role and KMS key policy may also need to allow decryption. Add KMS permissions only if your bucket's encryption configuration requires them.

---

## 5. Step 3 — Create a Databricks storage credential

1. Open your Databricks workspace.
2. Go to **Catalog → Connect → Credentials**.
3. Choose **Create credential**.
4. Select **Storage Credential**.
5. Set the credential type to **AWS IAM Role**.
6. Enter:

| Field | Value |
|---|---|
| Credential name | `s3_sales_credential` |
| Credential type | `AWS IAM Role` |
| IAM role ARN | Paste the ARN copied from your AWS IAM role |
| Comment | `Access to sales S3 bucket` |

7. Choose **Create**.

Databricks displays the IAM role ARN, an External ID, and a generated trust policy.

**Important:** Copy the External ID and complete trust policy from your own Databricks dialog. The External ID is specific to the credential. Do not use an example value or invent one.

---

## 6. Step 4 — Update the IAM role trust policy

The trust policy is separate from the S3 permissions policy.

1. Return to AWS IAM.
2. Open **Roles → DatabricksS3ReadAccess**.
3. Select **Trust relationships**.
4. Choose **Edit trust policy**.
5. Replace the existing trust policy with the complete policy generated by Databricks for your storage credential.
6. Save the policy.

The generated policy has this general structure. Replace the placeholders with the exact values from your Databricks credential dialog:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": [
          "DATABRICKS_AWS_IAM_PRINCIPAL_FROM_CREDENTIAL_DIALOG"
        ]
      },
      "Action": "sts:AssumeRole",
      "Condition": {
        "StringEquals": {
          "sts:ExternalId": "EXTERNAL_ID_FROM_CREDENTIAL_DIALOG"
        }
      }
    }
  ]
}
```

**Source of truth:** Use the complete trust policy generated by your Databricks workspace. Do not substitute a principal or External ID from another workspace or example. If Databricks provides more than one principal, preserve all principals in its generated policy.

---

## 7. Step 5 — Validate the storage credential

1. Return to Databricks.
2. Open **Catalog → Connect → Credentials**.
3. Select `s3_sales_credential`.
4. Choose **Validate Configuration** or **Validate Connection**, if available.
5. Review the result.

A credential appearing in the list does not prove that Databricks can assume the AWS role. Resolve validation errors before relying on it.

---

## 8. Step 6 — Create or inspect the external location

1. In Databricks, go to **Catalog → Connect → External Locations**.
2. If the location does not exist, choose **Create external location**.
3. Enter:

| Field | Value |
|---|---|
| Name | `sales_s3_location` |
| URL / storage path | Enter the S3 bucket or folder address in the Databricks form |
| Storage credential | Select the intended storage credential |

4. Run the validation option if available.
5. Create the external location.

### Verify the attached credential

Open `sales_s3_location` and inspect its **Overview** tab. Confirm which storage credential is actually attached.

If the displayed credential name is different from `s3_sales_credential`, do not assume they are interchangeable. Open the credential details and confirm that it references the intended IAM role and has the matching trust configuration. If you intended to use `s3_sales_credential`, verify or correct the association before testing.

---

## 9. Step 7 — Grant Unity Catalog permissions

1. Open `sales_s3_location`.
2. Select **Permissions**.
3. Choose **Grant** if the required privilege is missing.
4. Select the Databricks user or group.
5. Grant `READ FILES`.
6. Save the grant.

The permissions screen in the practice setup showed:

| Principal | Privilege |
|---|---|
| All account users | `READ FILES` |

`READ FILES` is the relevant external-location privilege for reading files, provided AWS authentication and other access controls are configured correctly.

For writing output later, grant `WRITE FILES` only when needed and add the corresponding S3 write permissions to the IAM role.

---

## 10. Step 8 — Read CSV files with PySpark

For a CSV file, use `spark.read.csv()`. Do not use the Parquet reader for a CSV file.

```python
sales = (
    spark.read
    .option("header", "true")
    .option("inferSchema", "true")
    .csv("YOUR_S3_BUCKET_OR_FOLDER_ADDRESS/sales.csv")
)

sales.show()
```

Read the customers file:

```python
customers = (
    spark.read
    .option("header", "true")
    .option("inferSchema", "true")
    .csv("YOUR_S3_BUCKET_OR_FOLDER_ADDRESS/customers.csv")
)

customers.show()
```

Replace `YOUR_S3_BUCKET_OR_FOLDER_ADDRESS` with the actual storage path in your environment.

Inspect the schema:

```python
sales.printSchema()
customers.printSchema()
```

### CSV and Parquet use different readers

```python
# CSV
df_csv = (
    spark.read
    .option("header", "true")
    .option("inferSchema", "true")
    .csv("YOUR_CSV_FILE_ADDRESS")
)

# Parquet
df_parquet = spark.read.parquet("YOUR_PARQUET_FILE_ADDRESS")
```

Assign the DataFrame before calling `.show()`. The `.show()` method displays rows and returns `None`, so do not assign the result of `.show()` to a DataFrame variable.

## 11. Step 9 — Run the filter, join, and aggregation exercise

After both CSV files load successfully:

```python
sales = (
    spark.read
    .option("header", "true")
    .option("inferSchema", "true")
    .csv("YOUR_S3_BUCKET_OR_FOLDER_ADDRESS/sales.csv")
)

customers = (
    spark.read
    .option("header", "true")
    .option("inferSchema", "true")
    .csv("YOUR_S3_BUCKET_OR_FOLDER_ADDRESS/customers.csv")
)

result = (
    sales
    .filter(sales.amount > 500)
    .join(customers, "customer_id")
    .groupBy("city")
    .sum("amount")
)

result.show()
```

This performs the following operations:

1. Reads the sales and customer datasets.
2. Keeps sales records where `amount` is greater than 500.
3. Joins the datasets using `customer_id`.
4. Groups the joined records by `city`.
5. Calculates the total sales amount for each city.

## 12. Optional — Write output to S3

The read-only policy in Step 2 does not permit writing. Before writing, arrange all of the following:

- Add `s3:PutObject` to the IAM role for the intended output folder.
- Add `s3:DeleteObject` only if the chosen write mode requires deleting or replacing existing objects.
- Grant the Databricks principal `WRITE FILES` on the external location.
- Follow your organization's approval process before granting write access.

Then write the result:

```python
result.write.mode("overwrite").parquet(
    "YOUR_S3_BUCKET_OR_FOLDER_ADDRESS/output/"
)
```

For practice, use a dedicated output folder and avoid overwriting source data.

## 13. Troubleshooting — `UNAUTHORIZED_ACCESS` or `403 Forbidden`

The original error included:

```text
AnonymousAWSCredentials
credential-header: no-credential-header
signature-present: false
```

This indicates that the failing S3 request was made without signed AWS credentials. It does not, by itself, mean that disabled ACLs are the problem.

Check these items in order:

1. **File format:** Is the file CSV or Parquet? Use the matching Spark reader.
2. **Storage credential:** Does it refer to the intended IAM role?
3. **Trust policy:** Does the IAM role trust the Databricks principal shown in the generated policy?
4. **External ID:** Does the trust policy contain the exact External ID generated for that credential?
5. **S3 permissions:** Does the IAM role have `s3:ListBucket` on the bucket and `s3:GetObject` on the required objects?
6. **External location:** Does it point to the correct bucket or folder and use the intended storage credential?
7. **Unity Catalog grants:** Does the Databricks user or group have `READ FILES`?
8. **Bucket policy:** Is there an explicit deny or a restriction that blocks the IAM role?
9. **Encryption:** If SSE-KMS is used, do the IAM role and KMS key policy permit decryption?
10. **Access path:** Confirm that the read is using the configured external location and its credential. Creating a storage credential does not automatically authenticate every S3 access path.

A useful listing test is:

```python
display(
    dbutils.fs.ls(
        "YOUR_S3_BUCKET_OR_FOLDER_ADDRESS"
    )
)
```

If listing fails, investigate authentication, bucket permissions, and external-location configuration before debugging the CSV contents.

## 14. Final verification checklist

- [ ] S3 bucket remains private.
- [ ] IAM role `DatabricksS3ReadAccess` exists.
- [ ] IAM role has the required S3 read permissions.
- [ ] Databricks storage credential exists.
- [ ] IAM trust policy uses the Databricks-generated principal and External ID.
- [ ] Storage credential validation succeeds.
- [ ] External location points to the intended bucket or folder.
- [ ] External location uses the intended storage credential.
- [ ] Databricks user or group has `READ FILES`.
- [ ] `sales.csv` loads successfully using `spark.read.csv()`.
- [ ] `customers.csv` loads successfully using `spark.read.csv()`.
- [ ] The filter, join, and aggregation return results.

**Do not mark the setup complete just because the credential or external location appears in the Databricks UI. Confirm successful validation and a real file read.**
